# Тест-кейсы: Sensum & Bakery — справочник бариста

Каталог проверок приложения. Каждый кейс привязан к реальной функции из `index.html`, `sw.js` или `tools/apps-script/Code.gs`; ожидаемый результат снят с работающего приложения (v1.90, 31.10.2026), а не придуман.

## Как пользоваться

**Автоматически (агент или вручную в код-сессии)** — из корня репозитория:

```bash
python3 -B tools/audit.py        # DATA-*   данные, фото, версии
node tools/apps-script/test.js   # GAS-*    скрипт таблицы результатов (на моках)
node tools/smoke.js              # большая часть NAV/CRD/SPT/PRM/SET/LNG/LRN/UI
node tools/cases.js              # остальное: FLT, FAV, CRD, VIT, CHG, LRN, PWA и KNOWN
```

Строки `tools/cases.js` начинаются с ID кейса из этого файла. Ни один прогон не пишет в настоящую таблицу и не шлёт сообщений в Telegram: бэкенд подменяется моком (код `1234` — тестовый сотрудник).

Агенту достаточно сказать: **«прогони тест-кейсы»** — `qa-checker` запустит всё и отчитается по ID. Можно сузить: «прогони P0», «проверь только обучение (LRN)».

**Вручную** — кейсы с пометкой `ручной`: их нельзя честно проверить в headless-браузере (настоящий iPhone, живая таблица, Telegram).

**Колонки:** `P` — приоритет (`P0` — без этого смена не работает, проверять перед каждым PR; `P1` — важно, перед каждым PR через автотесты; `P2` — раз в месяц или после больших изменений). `Чем` — где кейс автоматизирован: `audit`, `gas`, `smoke`, `cases`, `live` (только чтение живого скрипта), `ручной`.

**Когда что прогонять**

| Момент | Что |
|---|---|
| Перед каждым PR | все четыре команды выше: 0 FAIL |
| После merge и деплоя (~1 мин) | LIVE-01, PWA-04 на своём телефоне |
| Раз в месяц / перед экзаменом месяца | все `ручной` кейсы P0–P1 |

Найдены при составлении каталога. `tools/cases.js` проверяет их каждый прогон: пока проблема есть — строка `KNOWN` (прогон не падает); когда исправлено — строка `FIXED`, и кейс переносится в свой раздел как обычный.

| ID | P | Что происходит | Как воспроизвести | Решение |
|---|---|---|---|---|
| KNOWN-01 | P1 | Названия напитков записаны латиницей (Café Latte, Cappuccino), поэтому поиск по-русски не находит ничего: «латте», «капучино», «раф» → 0 карточек. Заготовки и витрина по-русски ищутся нормально | «Напитки» → в поиск «латте» | За владельцем: добавить в поиск русские варианты названий (например, поле синонимов) или оставить латиницу как стандарт и написать это в подсказке поля |
| KNOWN-02 | P2 | После просмотра «Изменений» бейдж «Обновлено» гаснет сразу, а «Новинка» (сейчас на Lotus Latte) висит до перезапуска приложения | Непрочитанная запись типа news → открыть «Изменения» → вернуться в «Напитки» | `markChangesSeen()` очищает `changedSet`, но не `newSet` — добавить `newSet.clear()` |
| KNOWN-03 | P2 | В рецепте заготовки «Жасминовый паудер» ингредиент «Жасминовый чай — 25 г» автоматически стал ссылкой на заготовку «Жасминовый чай (заготовка)» — заваренный чай для айс-ти (Apple Mint, Orange). Если для паудера берут сухой чай, ссылка ведёт бариста не туда; если заваренный — паудера нет в «Используется в» у чая | Заготовки → «Жасминовый паудер» → тап по «Жасминовый чай»; `python3 tools/audit.py` → WARN по jasminetea | За владельцем: сухой чай → переименовать ингредиент так, чтобы в нём не было «жасминовый чай» (например, «Чай с жасмином, листовой»); заваренный → добавить паудер в `usedin` заготовки чая |
