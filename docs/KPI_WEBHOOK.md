# Вебхук «Sensum Обучение» → KPI-система

Описание для разработчика KPI-системы: что присылает обучение, когда и как это проверить.
Версия формата: **1** (скрипт результатов v5.13; событие `training.day` с v5.14, `training.test` с v5.15).

## Коротко

- Раз в неделю, в **понедельник около 10:00 по Баку**, скрипт Google Таблицы «Sensum Обучение: результаты тестов» отправляет
  **один POST-запрос с JSON** на адрес, который даёт KPI-система.
- В запросе итоги **прошедшей календарной недели (пн–вс, время Баку)** по каждому сотруднику: тесты, уроки,
  выполнена ли недельная норма, «Вопрос дня», опыт (XP), совы и KPI обучения за месяц. В поле `text` лежит тот же отчёт,
  что тренинг-менеджер получает в Telegram.
- Если KPI-система не ответила кодом **2xx**, отправка повторяется каждый вечер (около 21:00), пока неделя не дойдёт.
- **Каждый тест** (тест недели, экзамен месяца, повтор ошибок) приходит сразу после сдачи — событие `training.test` (см. ниже).
- Кроме того, **сразу, как сотрудник выполнил «План на сегодня»** (все пункты плана в приложении), приходит событие
  `training.day` — один раз на сотрудника и день (см. ниже).
- Одна неделя может прийти **несколько раз** (повтор, ручная отправка). Ключ недели — поле `id`. Запись по неделе и сотруднику
  нужно **перезаписывать** (upsert), а не добавлять второй раз.

## Что нужно от KPI-системы

1. **Адрес** `https://…`, доступный из интернета: запрос приходит с серверов Google, а не из внутренней сети.
2. **Ключ доступа** (по желанию, но лучше с ним): любая длинная случайная строка. Тренинг-менеджер вводит адрес и ключ
   в таблице: меню **Sensum → 4. Подключить вебхук KPI-системы**. В коде и в репозитории их нет.
3. **Ответ 2xx** (200, 201, 202 или 204) в течение 30 секунд. Тело ответа не читается. Любой другой код или таймаут
   считается ошибкой: тренинг-менеджеру приходит сообщение, вечером запрос повторяется.

## Запрос

```
POST <адрес вебхука>
Content-Type: application/json
X-Sensum-Event: training.week
X-Sensum-Delivery: sensum-learn:week:2026-11-16
Authorization: Bearer <ключ>                          (только если ключ задан)
X-Sensum-Signature: sha256=<hex HMAC-SHA256 тела>     (только если ключ задан)
```

`X-Sensum-Signature` — HMAC-SHA256 **сырого тела запроса** (байты UTF-8, как пришли) с ключом доступа, в шестнадцатеричном виде.
Достаточно проверять что-то одно: `Authorization` (проще) или подпись (надёжнее: подтверждает, что тело не изменено).
Подпись сравнивайте с телом **до** разбора JSON.

Node.js:

```js
const crypto = require('crypto');
function verify(rawBody, header, secret) {
  const want = 'sha256=' + crypto.createHmac('sha256', secret).update(rawBody).digest('hex');
  return header && header.length === want.length && crypto.timingSafeEqual(Buffer.from(header), Buffer.from(want));
}
```

Python:

```python
import hmac, hashlib
def verify(raw_body: bytes, header: str, secret: str) -> bool:
    want = 'sha256=' + hmac.new(secret.encode(), raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(want, header or '')
```

### Поля верхнего уровня

| Поле | Тип | Что значит |
|---|---|---|
| `event` | строка | `training.week` — итоги недели. Ещё бывает `ping` (см. ниже). |
| `version` | число | Версия формата. Поля внутри версии только добавляются; переименование или удаление — новая версия. |
| `id` | строка | Ключ недели: `sensum-learn:week:<понедельник>`. Повтор приходит с тем же `id`. |
| `sentAt` | строка | Время отправки, ISO 8601, UTC. При повторе новое. |
| `week.from`, `week.to` | `YYYY-MM-DD` | Понедельник и воскресенье недели, время Баку. |
| `week.month` | `YYYY-MM` | Месяц, к которому относится неделя: месяц её воскресенья. |
| `trial` | bool | `true`, пока KPI обучения в пробном режиме: цифры считаются, но минус не предлагается. |
| `rules` | объект | Нормы, по которым всё посчитано: тестов в неделю (стажёр / остальные), уроков в неделю, проходной % теста, порог и потолок минуса KPI. |
| `summary` | объект | Итог по всем сотрудникам (поля как у филиала). |
| `branches[]` | массив | Итоги по филиалам: `staff` — сотрудников, `tested` — сдавали хоть один тест, `fullWeek` — выполнили норму, `tests` — тестов всего, `avgScore` — средний % (или `null`), `owls` — сов за неделю. |
| `employees[]` | массив | По одному на сотрудника, отсортированы по филиалу и имени. |
| `text` | строка или `null` | Текст отчёта из Telegram на момент отправки (последние 7 дней). |

### Сотрудник (`employees[]`)

| Поле | Тип | Что значит |
|---|---|---|
| `code` | строка | 4-значный код сотрудника в обучении (лист «Сотрудники»). Стабилен. |
| `kpiId` | строка или `null` | ID сотрудника в KPI-системе: столбец G «ID в KPI-системе» листа «Сотрудники», если тренинг-менеджер его заполнил. **Сопоставлять лучше по нему**, иначе по `code`. |
| `name`, `branch`, `role` | строка | Имя, филиал и должность, как в листе. |
| `level` | строка или `null` | `trainee` (стажёр), `barista`, `senior` или `null`. |
| `tests.done` / `tests.need` | число | Зачётные тесты недели (от 70%, по одному в день) и норма: 3, у стажёра 5. `done` не больше `need`. |
| `tests.taken` | число | Сколько зачётных тестов пройдено всего, включая слабые и сверх нормы. |
| `tests.belowLine` | число | Завершены ниже 70% (не засчитаны). |
| `tests.overLimit` | число | Сверх нормы недели или второй за день (не засчитаны). |
| `tests.aborted` | число | Прерваны. |
| `tests.away` | число | Сколько раз сотрудник выходил из приложения во время тестов. |
| `tests.avgScore` | число или `null` | Средний % зачётных попыток (прерванный = 0, сверх нормы не входят); `null`, если тестов не было. |
| `lessons.done` / `lessons.need` | число | Уроки, засчитанные на этой неделе, и норма (2). |
| `fullWeek` | bool | Норма недели выполнена: тесты и уроки. |
| `exam` | объект или `null` | «Экзамен месяца», если сдавался на этой неделе: `score`, `total`, `percent`, `aborted`. |
| `dailyQuestion.days` | число | В сколько дней недели отвечал на «Вопрос дня». |
| `dayPlans` | число | В сколько дней недели выполнил «План на сегодня» целиком (с v5.14; дни, о которых пришло `training.day`). |
| `xp` | число | Опыт за неделю (игровые очки обучения). |
| `owls.earned` | число | Совы, начисленные за эту неделю. |
| `owls.items[]` | массив | За что: `why`, `n`, `credited` — отмечены ли уже как перенесённые в KPI-систему. |
| `absentDays` | число | Дни недели в отпуске или на больничном (лист «Отсутствия»). |
| `startedOn` | `YYYY-MM-DD` или `null` | Начало работы новичка: первые 14 дней минус KPI не начисляется. |
| `kpiMonth` | объект | KPI обучения за месяц `week.month` по прошедшим неделям: `pct` — % выполнения плана, `parts` — недели / экзамен / качество / регулярность в %, `loss` — предложенный минус в % (0–30), `examPending` — экзамен ещё не сдан, `lossIfExamMissed` — минус, если не сдать, `state` — `trial` или `live`. Окончательное решение по минусу принимает тренинг-менеджер в таблице. |

В отправку не попадают неактивные сотрудники и тестовый аккаунт тренинг-менеджера (филиал «Тест»).

## Событие `training.day` — «План на сегодня» выполнен

В приложении у сотрудника каждый день есть «План на сегодня»: до трёх пунктов — **«Вопрос дня»** (`daily`), **учёба** (`study`:
следующий урок или колода карточек) и **тест** (`test`: зачётный тест недели или экзамен месяца). Если тест сегодня уже недоступен
(норма недели сдана или тест сегодня уже был), пункта теста в плане нет. Когда выполнены **все** пункты, приложение сообщает
об этом таблице, а скрипт сразу отправляет событие на тот же адрес, с теми же заголовками и подписью.

```json
{
  "event": "training.day",
  "version": 1,
  "id": "sensum-learn:day:2026-11-27:9001",
  "source": "sensum-learn",
  "scriptVersion": "v5.14",
  "sentAt": "2026-11-27T12:00:03.000Z",
  "day": "2026-11-27",
  "week": "2026-11-23",
  "month": "2026-11",
  "trial": true,
  "employee": { "code": "9001", "kpiId": null, "name": "Тест-1", "branch": "Central Park", "role": "Бариста", "level": "barista" },
  "plan": { "complete": true, "steps": ["daily", "study", "test"], "done": ["daily", "study", "test"], "completedAt": "2026-11-27T12:00:02.000Z" },
  "facts": {
    "tests": [ { "kind": "mixed", "score": 9, "total": 10, "percent": 90, "counted": true, "aborted": false } ],
    "dailyQuestion": { "score": 3, "total": 3, "aborted": false },
    "lessons": ["cf-3", "cf-4"],
    "xp": 140
  }
}
```

| Поле | Что значит |
|---|---|
| `id` | Ключ: `sensum-learn:day:<день>:<код>`. Одна запись на сотрудника и день, повтор перезаписывает. |
| `day`, `week`, `month` | День (Баку), понедельник его недели и месяц. |
| `employee` | Как в `employees[]` недельного события: `code`, `kpiId`, `name`, `branch`, `role`, `level`. |
| `plan.steps` | Какие пункты были в плане в этот день: `daily`, `study`, `test` (два или три). |
| `plan.done` | Какие выполнены — приходит, только когда выполнены все, поэтому совпадает со `steps`; `complete` всегда `true`. |
| `plan.completedAt` | Когда таблица получила отметку, ISO 8601, UTC. |
| `facts.tests[]` | Тесты этого дня из таблицы: вид (`mixed` — тест недели, `exam` — экзамен месяца, `mix` — повтор ошибок), баллы, `counted` — засчитан в норму недели (только тест недели от 70%, не сверх нормы). |
| `facts.dailyQuestion` | «Вопрос дня» этого дня или `null`. |
| `facts.lessons` | Уроки, засчитанные в этот день (id уроков приложения). Колоды карточек в таблицу не приходят, поэтому их здесь нет. |
| `facts.xp` | Опыт за день: тесты и «Вопрос дня». |

Невыполненный план не отправляется. Если KPI-система не ответила 2xx, отметка остаётся на листе «План дня» со статусом «ошибка»,
и вечерняя сводка повторяет все недошедшие отметки за последние 7 дней. Тренинг-менеджер получает одно сообщение в Telegram за вечер,
пока что-то не доходит.

## Событие `training.test` — сдан тест

Приходит сразу после того, как результат теста записан в таблицу: один раз на попытку. Повтор той же попытки (телефон не получил
ответ и отправил снова) второй раз не уходит. «Вопрос дня» этим событием не приходит — он есть в `training.day`.

```json
{
  "event": "training.test",
  "version": 1,
  "id": "sensum-learn:test:mw0example001",
  "source": "sensum-learn",
  "scriptVersion": "v5.15",
  "sentAt": "2026-11-27T13:14:05.000Z",
  "day": "2026-11-27",
  "week": "2026-11-23",
  "month": "2026-11",
  "trial": true,
  "employee": { "code": "9001", "kpiId": null, "name": "Тест-1", "branch": "Central Park", "role": "Бариста", "level": "barista" },
  "test": {
    "attemptId": "mw0example001",
    "kind": "mixed",
    "scope": "Общий тест",
    "score": 6, "total": 10, "percent": 60,
    "passed": false, "counted": false, "overLimit": false, "aborted": false,
    "time": "1:56", "timeouts": 1, "away": 0,
    "lang": "ru", "appVersion": "1.129",
    "takenAt": "2026-11-27T13:12:09.000Z",
    "xp": 60,
    "mistakes": ["Ваниль-паудер: какой срок хранения? → 2 месяца (верно: 1 месяц)"]
  }
}
```

| Поле | Что значит |
|---|---|
| `id` | Ключ: `sensum-learn:test:<id попытки>`. Одна запись на попытку, повтор перезаписывает. |
| `day`, `week`, `month` | День сдачи (Баку), понедельник его недели, месяц. |
| `test.kind` | `mixed` — тест недели, `exam` — экзамен месяца, `mix` — повтор ошибок; у старых версий приложения `drinks`, `preps`, `vitrina`, `theory`. |
| `test.score` / `total` / `percent` | Верных ответов, вопросов, процент (прерванный тест — 0). |
| `test.passed` | Сдан: не прерван и не ниже порога сдачи из таблицы (сейчас 70%). |
| `test.counted` | Засчитан в норму недели: тест недели от 70%, не сверх нормы и не второй за день. |
| `test.overLimit` | Сверх нормы недели или второй зачётный тест за день: сохранён, но без XP и без зачёта. |
| `test.aborted` | Прерван (вышел из теста или закрыл приложение). |
| `test.time`, `timeouts`, `away` | Время прохождения (м:сс), сколько раз вышло время на ответ, сколько раз выходил из приложения. |
| `test.xp` | Опыт за этот тест. |
| `test.mistakes[]` | Ошибки: «вопрос → ответ (верно: …)». |

Если KPI-система не ответила 2xx, попытка записывается на листе «Отправки в KPI» как «ошибка», и вечерняя сводка повторяет
недошедшие тесты за последние 7 дней.

## Событие `ping`

Приходит, когда тренинг-менеджер сохраняет адрес вебхука в меню, — проверка связи. Поля: `event: "ping"`, `version`, `id`,
`source`, `scriptVersion`, `sentAt`, `text`. Ответьте 2xx и ничего не сохраняйте.

## Повторы и порядок

- Автоматически повторяется только **последняя закончившаяся неделя**, каждый вечер, пока не будет 2xx.
- Отметки «План на сегодня» и тесты повторяются каждый вечер, пока не дойдут, но не старше 7 дней.
- Тренинг-менеджер может отправить ту же неделю вручную (меню «Отправить итоги прошлой недели в KPI-систему сейчас»).
  Например, когда сотрудник досдал тест офлайн и результат пришёл позже. Данные тогда свежее: перезаписывайте.
- Каждая попытка записана на листе «Отправки в KPI»: время, неделя, сколько сотрудников, код ответа, статус.

## Проверка

1. На стороне KPI-системы поднимите эндпоинт и дайте тренинг-менеджеру адрес и ключ.
2. В таблице: **Sensum → 4. Подключить вебхук KPI-системы** → адрес → ключ. Придёт `ping`, в таблице появится сообщение с кодом ответа.
3. **Sensum → Отправить итоги прошлой недели в KPI-систему сейчас** — придёт настоящая неделя.
4. Отключить отправку: тот же пункт 4 с пустым адресом.
